Zum Nachschlagen

Dein Code-Spickzettel.

Die wichtigsten Bausteine, ihre Bedeutung und die Verbindung zum echten Arduino.

Der Rahmen bleibt gleich

void setup() {
  // Einmal beim Start ausführen.
  pinMode(13, OUTPUT);
}

void loop() {
  // Danach immer wieder ausführen.
  digitalWrite(13, HIGH);
}

void bedeutet: Diese Funktion gibt keinen Wert zurück. Die geschweiften Klammern { } halten zusammen, was zur Funktion gehört.

Ein Block. Eine Anweisung.

BlockideeTextcode
Pin als AusgangpinMode(13, OUTPUT);
LED einschaltendigitalWrite(13, HIGH);
LED ausschaltendigitalWrite(13, LOW);
Eine Sekunde wartendelay(1000);

Die Befehle werden von oben nach unten ausgeführt. delay() hält den normalen Programmablauf an. 1.000 Millisekunden sind 1 Sekunde.

Werte mit Namen

const int led = 13;   // bleibt gleich
int pause = 250;       // kann sich ändern

digitalWrite(led, HIGH);
delay(pause);

int speichert ganze Zahlen. Ein Name ersetzt einen festen Wert und macht den Code lesbarer. Ein Name muss zuerst deklariert werden. Groß- und Kleinschreibung zählen!

Wenn … dann … sonst

if (digitalRead(2) == LOW) {
  digitalWrite(13, HIGH);
} else {
  digitalWrite(13, LOW);
}

== vergleicht zwei Werte. = weist einen Wert zu. Bei INPUT_PULLUP und einem Taster nach GND gilt: gedrückt = LOW, losgelassen = HIGH.

Eine feste Anzahl wiederholen

for (int i = 0; i < 3; i++) {
  digitalWrite(13, HIGH);
  delay(250);
  digitalWrite(13, LOW);
  delay(250);
}

Start: i = 0. Solange i < 3 gilt, wird wiederholt. Nach jeder Runde erhöht i++ den Zähler um 1. Es gibt drei Durchläufe: 0, 1 und 2.

Die kleine Fehler-Checkliste

  • Endet jede Anweisung mit einem ;?
  • Passen alle ( ) und { } zusammen?
  • Steht dort digitalWrite und nicht digitalwrite?
  • Sind HIGH, LOW und OUTPUT großgeschrieben?
  • Wurde der Pin in setup() eingerichtet?
  • Steht das Wiederholte in loop()?

Eine Fehlermeldung nennt häufig die Stelle, an der der Fehler auffällt. Die Ursache kann eine Zeile davor liegen.

Vom Bildschirm auf den Tisch

Pin 13 → 220–330 Ω → LED rot → GND
Pin 12 → 220–330 Ω → LED gelb → GND
Pin 11 → 220–330 Ω → LED grün → GND
Pin 2  → Taster → GND

Gedacht für ein Arduino Uno mit 5-V-Logik. Jede externe LED bekommt einen eigenen Vorwiderstand. Die lange LED-Anschlussleitung (Anode) zeigt zum Widerstand; die Kathode zeigt zu GND. Vor dem Umbauen USB abziehen.

Für die ersten Blinkübungen reicht die eingebaute LED an Pin 13 (LED_BUILTIN) ohne externe LED. Der Taster nutzt den internen Pull-up-Widerstand; deshalb ist kein externer Tasterwiderstand nötig.

Übertragen: .ino-Datei herunterladen → in der Arduino IDE öffnen → passendes Board und Port wählen → dort überprüfen und hochladen.

Was die Lernsimulation versteht

Unterstützt werden setup(), loop(), ganze Zahlen und boolesche Werte, const, pinMode(), digitalWrite(), digitalRead(), delay(), if/else, for und einfache Rechen- und Vergleichsoperatoren. Die sichtbaren LEDs liegen an 13, 12 und 11; der Taster liegt an 2. Der Taster-Schalter hält den gedrückten Zustand, bis du ihn erneut anklickst.

Die Simulation zeigt mehrere Schleifendurchläufe bis zur Zeit- oder Schrittgrenze und hält danach an. Prüfungen betrachten das Verhalten ausgewählter Pins, keine vollständige C++-Semantik. Bibliotheken, Serial, analoge Sensoren, eigene Funktionen und echte elektrische Eigenschaften sind hier nicht abgebildet. Ein gespeicherter Haken bestätigt, dass du die Aufgabe mindestens einmal gelöst hast.

Fachliche Grundlagen: offizielle Arduino-Sprachreferenz, Blink-Beispiel und Taster mit INPUT_PULLUP. Diese Links benötigen Internet.

Für den Unterricht

Der Übergang darf klein sein.

Ein fertiger Lernpfad mit abgestuften Hilfen, Modellhardware und Platz zum Experimentieren.

Ein möglicher Einstieg · 2 × 45 Minuten

  • 10 Min: Vorwissen aktivieren. Was passiert beim Start? Was wiederholt sich?
  • 20 Min: Übungen 1–2 gemeinsam oder im Tandem: Blöcke legen, Code vorlesen, Wirkung vorhersagen.
  • 15 Min: Übungen 3–4: Werte verändern und begründen, warum sich das Verhalten ändert.
  • 20 Min: Übungen 5–6: Entscheidungen und Wiederholungen.
  • 15 Min: Fehlerdetektiv und eigene Mission.
  • 10 Min: Einen Sketch erklären und gegebenenfalls auf ein echtes Board übertragen.

Als Auswahl nutzen: Lernende müssen nicht alle acht Übungen in einer Stunde schaffen. Die Zeitangaben sind Orientierung für Lernende mit Blockerfahrung.

Tandems & Differenzierung

Rollenwechsel: Eine Person schreibt oder schiebt, die andere erklärt jede Zeile. Nach einem Test tauschen.

Unterstützung: Erst Code vorlesen, dann mit dem Spickzettel vergleichen, erst danach die gestuften Tipps öffnen. In den Blockübungen ist Klicken eine Alternative zum Ziehen.

Vertiefung: Andere Pins und Zeiten wählen, eine vierte Ampelphase ergänzen oder eine eigene Blinkbotschaft entwickeln. Warum reagiert ein Taster während delay() verzögert?

Exit-Ticket: „Was gehört in setup()? Was in loop()? Erkläre eine Zeile mit deinen eigenen Worten.“

Rückmeldung & Datenschutz

Der Test prüft Syntax und ausgewählte Verhaltenskriterien. Ein lauffähiger Sketch kann die Aufgabe noch verfehlen. Bei der Tasterübung werden beide Zustände geprüft.

Entwürfe, Haken und Tipps bleiben lokal im Browser gespeichert, soweit dessen Einstellungen es erlauben. Es gibt keine Anmeldung, keine Analyse und keine Übertragung von Lernständen. Bei gemeinsam genutzten Geräten vor der nächsten Gruppe zurücksetzen.

Der Lernstandexport ist eine lokale Textdatei mit erledigten Aufgaben. Er ist eine Orientierung und keine automatische Benotung.

Bedienung & Einsatz

Die HTML-Datei lässt sich direkt öffnen, kopieren und im schulischen Netzwerk verteilen. Alle Inhalte und Funktionen sind eingebettet. Schriftarten und Bibliotheken werden nicht nachgeladen.

Tastatur: Mit Tab zu Blöcken und Ablageflächen wechseln, mit Enter aktivieren. In einer Ablage verschieben die Pfeil-Schaltflächen einen Block nach oben oder unten. Im Codefeld fügt Tab zwei Leerzeichen ein; mit Esc verlässt du das Feld per Tab wieder.

Die .ino-Dateien sind reguläre Sketch-Dateien für die Arduino IDE. Vor einem Hardware-Einsatz dort kompilieren und die reale Verdrahtung prüfen.

Lösungen zum gemeinsamen Besprechen

Eine mögliche Lösung pro Übung. Unterschiedliche Programme können dasselbe Verhalten erzeugen. Die Lösungen sind bewusst hier gesammelt, damit die Lernansicht schrittweise bleibt.
